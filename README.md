# Dry Fruits Around the World

A data analytics and forecasting project using FAOSTAT crop-production records. The project includes a Python analysis/model-training workflow, cleaned and model-ready datasets, exported results, plots, and a static interactive dashboard.

## What the Python model predicts

The model predicts **the next year's crop production, in tonnes, for each country and selected crop item** (for example, almond production in a particular country). It uses the previous one, two, and three years of production, harvested area, and yield, along with the country and crop-item labels. The supplied forecast output is for **2025**, based on historical data through 2024, and includes only country-item series with enough usable history.

For evaluation, the script trains on observations through 2021 and tests predictions for 2022-2024 against recorded production. This is a crop-production forecast—not a prediction of dried-fruit consumption, prices, exports, or nutritional value. The FAOSTAT items are crop categories (including nuts, dates, and figs), not a comprehensive set of processed dried-fruit products.

## Data source and scope

The original source file, [`data/raw/DRY FRUIT COUNTRY WISE.csv`](./data/raw/DRY%20FRUIT%20COUNTRY%20WISE.csv), is the FAOSTAT **Crops and livestock products (QCL)** export. It contains 43,471 records and 15 FAOSTAT fields, including area, item, element, year, unit, value, flags, and notes. The file contains 144 areas and 12 source items; the script filters it to 129 countries/areas and the nine items listed below, then creates the cleaned dataset under `outputs/`.

The cleaning workflow in `dry_fruits_production_analysis.py` selects the following nine items:

- Almonds
- Brazil nuts
- Cashew nuts
- Chestnuts
- Dates
- Figs
- Hazelnuts
- Pistachios
- Walnuts

This project uses FAOSTAT crop-production categories as a practical proxy for a dry-fruit/nut topic. It is **not** a complete dataset of processed dried foods: the crop categories include nut production (often reported in shell), dates, and figs. Raisins and prunes are not included as dried products. Grapes, plums, and apricots are excluded by the script because the selected FAOSTAT rows represent those crops, not their dried forms.

### Cleaned data fields

| Column | Meaning | Unit |
| --- | --- | --- |
| `Country` | Country/area name, with several names standardized for display | — |
| `Dry_Fruit` | Selected FAOSTAT crop item | — |
| `Year` | Reporting year | calendar year |
| `Area_Harvested` | Harvested area | hectares |
| `Production` | Crop production | tonnes |
| `Yield` | Reported or calculated yield | kg/ha |

The generated cleaned file covers 2000 through 2024. Country/item combinations do not all have observations in every year. The script drops rows whose production value is missing, preserves recorded zero-production rows, removes negative values and duplicate natural keys, and calculates yield from production and area only when yield is missing and area is positive. The cleaned output contains 7,935 rows, 129 distinct country/area labels, and no duplicate `Country` + `Dry_Fruit` + `Year` keys. It has 408 zero-production rows and missing yield values in some retained rows; missing values should not be interpreted as zero.

## Analysis and model training

The main implementation is [`dry_fruits_production_analysis.py`](./dry_fruits_production_analysis.py). It performs the following steps:

1. **Read and inspect the raw FAOSTAT export.** Reports columns, years, items, element/unit values, missing data, flags, duplicates, and basic summaries.
2. **Clean and reshape the records.** Removes unusable/missing values, excludes the overlapping `China` aggregate, standardizes selected names, keeps the nine listed items, pivots FAOSTAT elements into production/area/yield columns, and writes `outputs/clean_dry_fruits_data.csv`.
3. **Explore the data.** Calculates cumulative production by country/item, yearly totals and growth, and relationships among production, area, and yield. It saves charts under `outputs/figures/`.
4. **Build lag features.** For each country-item series, creates one-, two-, and three-year lags for production, harvested area, and yield. A complete annual grid is used so a lag means a calendar-year offset, not merely the previous available row.
5. **Select the model family without looking at the final test.** Random Forest and XGBoost are compared using pooled MAE over four expanding-window validation folds from the training period. A previous-year baseline is scored on those same validation rows as a reference.
6. **Tune and evaluate.** The selected family is tuned using the training-only chronological folds. The final 2022-2024 holdout is not used for model-family choice or hyperparameter search; it is reserved for the reported final evaluation.
7. **Refit and forecast.** The tuned model is refit using all labeled data through 2024 and predicts 2025 for country-item series with the required lag history.
8. **Export results.** Writes model-ready/test/forecast data, KPI JSON, browser dashboard data, plots, and a serialized model when run in an environment with the required dependencies and paths configured.

### Model features, target, and metrics

- **Target:** production in tonnes for the prediction year.
- **Categorical features:** country and dry-fruit item, one-hot encoded.
- **Numeric features:** lagged production, area harvested, and yield for years `t-1`, `t-2`, and `t-3`. The model does not use same-year production/area/yield as predictors.
- **Selection and final test design:** model-family selection and tuning use training years through 2021 only. The 2022-2024 chronological holdout is reserved for final evaluation. Each test-year prediction uses observed lag values from earlier years, so this evaluates rolling one-year-ahead predictions; it does not test recursively forecasting multiple future years without new observations.
- **Metrics:** MAE and RMSE (tonnes), R-squared, MAPE, and WAPE. MAPE excludes observations whose actual production is zero; percentage metrics can still be sensitive to very small actual values.
- **Forecast scope:** the checked forecast file contains 298 country-item rows across 8 of the 9 selected items. It does not represent every possible country-item combination, because the script requires usable recent lag history.

### Selected model, tuning validation, and hypothesis test

Model-family selection now happens strictly inside the training period: the script compares Random Forest and XGBoost using pooled MAE from four expanding-window folds (2014-2015, 2016-2017, 2018-2019, and 2020-2021). The previous-year baseline is measured on the same rows for context, but the family choice is based on the prespecified primary metric, MAE. The dashboard reports these cross-validation metrics and marks the selected family.

Hyperparameter search then tunes the selected family using those chronological training folds. Because the same training folds support selection and tuning, their scores are model-development evidence and may be optimistic; they are not the final generalization estimate. The 2022-2024 holdout is not used in either choice and provides the final evaluation. After reporting the holdout comparison, the tuned configuration is refit on all labeled data through 2024 to produce 2025 forecasts.

The dashboard reports per-fold tuning MAE and training/validation row counts, plus year-by-year holdout MAE, RMSE, and WAPE for the tuned model and previous-year baseline.

The final model comparison uses a one-sided paired test of absolute errors on the same held-out country/item/year rows, with standard errors clustered by country-item series. This preserves the row-weighted mean error difference while accounting for repeated annual observations within a series:

- **H0:** the selected tuned model's mean absolute error is greater than or equal to the previous-year baseline's (mean paired difference ≥ 0).
- **H1:** the selected tuned model has lower mean absolute error than the previous-year baseline (mean paired difference < 0).
- The dashboard displays the computed test statistic, p-value, mean paired difference, 95% confidence interval, and number of country-item clusters. The inference treats different country-item series as independent; common global shocks could still correlate series, and only one temporal holdout is available. Treat it as limited evidence, not proof of universal performance.

The paired-error graph plots the mean tuned-minus-baseline difference and its cluster-robust 95% confidence interval against zero. Negative values favor the tuned model; an interval crossing zero indicates the data are compatible with no mean difference at the 95% confidence level. Do not adjust the significance threshold or alter the evaluation after seeing the holdout result to force a desired conclusion.

#### Separate production-trend hypothesis

The dashboard also tests a different question about the historical data: **did annual global production of the selected crops have a positive linear trend from 2000 through 2024?** This is separate from whether one forecasting model beats another.

- **H0:** the linear trend slope is zero or negative (slope ≤ 0).
- **H1:** the linear trend slope is positive (slope > 0).
- **Method:** one-sided t-test for the OLS time-trend slope with Newey-West heteroskedasticity-and-autocorrelation-consistent (HAC) standard errors. The HAC lag length is 2 years, selected by the Newey-West rule used in the script.
- **Checked result:** estimated slope **+5.971 million tonnes per decade**, HAC standard error **0.150 million tonnes per decade**, *t*(23) = **39.832**, one-sided *p* = **5.02 × 10⁻²³**. At α = 0.05, reject H0; the annual totals provide statistically significant evidence of a positive linear trend in this dataset.

The dashboard's trend-hypothesis graph overlays that fitted linear line on the observed annual production totals; the line is the trend tested by the reported HAC t-test.

This result is **exploratory** because the rising production pattern was already visible in the annual trend chart before this test was added. HAC errors adjust for short-lag serial dependence approximately, but the test has only 25 annual observations and does not establish that time caused the increase. Report the trend test as a historical-data result, not as proof that the forecast model is accurate or that the model-comparison hypothesis passed.

### Local rerun verification

The latest reproducible local run uses Python 3.13.2, scikit-learn 1.8.0, and XGBoost 3.4.1. It reads 43,471 raw records and generates cleaned/model-ready data, model-selection CV results, final holdout metrics, a tuned model, and 2025 forecasts. Exact results are written to the output CSVs and dashboard payload by the pipeline; rerun the script after changing inputs or code so the published figures remain synchronized.

Training-only model-family selection used pooled MAE across the same 2,364 validation rows:

| Candidate/reference | Pooled CV MAE (tonnes) |
| --- | ---: |
| Random Forest (selected ML family) | 10,121.29 |
| XGBoost | 11,540.86 |
| Previous-year baseline (reference) | 9,184.61 |

Random Forest was selected **between the two ML families** because its CV MAE was lower than XGBoost's. The simpler previous-year method remains a reference baseline and performed better on CV MAE than either ML family; therefore, selecting Random Forest does not imply that ML beat the baseline.

Random Forest tuning produced a best mean fold MAE of **9,857.44 tonnes**. The final 2022-2024 holdout comparison was:

| Method | MAE (tonnes) | RMSE (tonnes) | R-squared | MAPE | WAPE |
| --- | ---: | ---: | ---: | ---: | ---: |
| Random Forest, tuned | 11,310.40 | 42,102.49 | 0.9749 | 37.66% | 12.00% |
| Random Forest, untuned | 11,644.34 | 46,480.48 | 0.9694 | 22.55% | 12.35% |
| XGBoost, untuned | 12,063.15 | 44,970.04 | 0.9714 | 177.99% | 12.79% |
| Previous-year baseline | 11,547.03 | 47,275.77 | 0.9683 | 17.35% | 12.25% |

The tuned model's MAE was **236.64 tonnes lower** than the previous-year baseline on the holdout, but the country-item clustered comparison was not statistically significant: *t*(300) = **−0.256**, one-sided *p* = **0.3990**, and the cluster-robust 95% confidence interval was **[−2,053.62, 1,580.35] tonnes**. Thus, fail to reject H0; these results do **not** establish that the tuned model is superior. There were 301 country-item clusters among the 878 held-out rows. The interval includes zero and the test uses just one 2022-2024 evaluation period, so report the model result as inconclusive.

## Dashboard implementation and accuracy

The dashboard is best described as a **Python-generated interactive HTML dashboard**, not a Python web application. The Python pipeline writes the latest values and forecast records to `outputs/dashboard_data.js`; `index.html` and `dashboard.js` render them in the browser. Plotly is loaded from its CDN, so charts need internet access. Rerun the Python script to refresh its dashboard data after changing the source or model. The project folder must remain together so the page can load `dashboard.js` and `outputs/dashboard_data.js`.

The dashboard now includes:

- Headline cards with the cumulative-production period clearly stated.
- The previous dashboard's visual style and vivid, distinct per-country world-map colors, with crop and year filters. Hover shows each country's leading crop and production in tonnes. The cumulative option sums production over the selected historical period.
- The previous pastel crop donut, blue annual-production trend, and colorful top-forecast chart, alongside current top-country, year-over-year production growth, and transformed-correlation charts.
- A gallery of all 18 figures generated by the Python workflow, including trend and ranking plots, production/area/yield relationships, model prediction diagnostics, and feature-importance charts.
- Baseline and tuned-model results from the latest run.
- The selected-model name and training-only CV rationale, model-family comparison, chronological tuning folds, validation MAE, and a cluster-aware paired holdout comparison against the previous-year baseline.
- A separate exploratory hypothesis test for a positive linear trend in annual global production, with Newey-West HAC standard errors and its actual conclusion.
- **Country/area and crop selectors** that look up a corresponding 2025 forecast, with a crop-by-crop chart that updates for the selected country. The page shows only combinations with available predictions (298 rows across 113 countries/areas and 8 selected crops).

The selectors display already-computed Python model forecasts; they do not execute the serialized model inside the browser or create new forecasts. 2025 values are estimates, not recorded 2025 production. The statistical chart section uses only current clean-data correlations; old mismatched regression and hypothesis-test summaries are not included.

The cumulative-production cards refer to the sum across country-item-year records from 2000 through 2024 (527,216,511.85 tonnes), not a single-year total. The country chart compares cumulative production on a shared numeric scale. Correlations are calculated on log(1 + value) variables and do not establish causation.

## Running the project

### View the website

For the most reliable preview, open a terminal in the project directory (the folder containing `index.html`) and run:

```powershell
python -m http.server 8000
```

Then open `http://localhost:8000`. The page reads the generated `outputs/dashboard_data.js` file and loads Plotly from a CDN, so keep the project folders together and allow internet access.

### Publish free with GitHub Pages

The dashboard is a static site. GitHub Pages serves the existing `index.html`; it does not run the Python training script. The raw CSV is a public FAOSTAT export, and this repository includes it so the analysis can be reproduced. Anything pushed to a public repository can be viewed and downloaded by others.

1. Sign in to GitHub and create a **new public repository**. Do not initialize it with a README, license, or `.gitignore`; this project already has those files.
2. Open PowerShell in the project folder (the folder containing `index.html` and `README.md`):

   ```powershell
   cd "C:\Users\samiksha\Downloads\Dry_Fruits_Complete_Project_Website\Dry_Fruits_Complete_Project_Website"
   ```

3. Initialize Git, review what will be uploaded, and make the first commit:

   ```powershell
   git init -b main
   git add .
   git status
   git commit -m "Prepare dry-fruit analytics dashboard"
   ```

   Check the `git status` list before committing. The `.gitignore` excludes the Python cache, local environments, the old dashboard reference, and `outputs/final_model.joblib`; it keeps the raw FAOSTAT CSV and the generated dashboard data/figures required by the site.

4. On the new GitHub repository page, copy its HTTPS URL, then connect and push the local branch:

   ```powershell
   git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
   git push -u origin main
   ```

   Replace the URL with the one GitHub shows for your repository. Sign in through the browser if Git requests authentication.

5. In GitHub, open **Settings → Pages**. Under **Build and deployment**, choose **Deploy from a branch**, select branch **`main`** and folder **`/(root)`**, then save.
6. Wait for the Pages deployment to finish. GitHub displays the live URL on the Pages settings screen; it usually has the form `https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/`. Open it and check the dashboard, forecast selector, map, and gallery. Plotly charts need internet access.

For later updates, regenerate outputs locally if the data/model changes, then run:

```powershell
git add .
git status
git commit -m "Update dashboard data"
git push
```

GitHub Pages redeploys after the push. The local Python analysis is not executed by Pages; rerun `dry_fruits_production_analysis.py` on your computer first if you need fresh generated data.

### Run the Python workflow

In Google Colab, run the script and upload the **raw FAOSTAT export** when prompted. Locally, install the packages from `requirements.txt`, then run:

```powershell
$env:PYTHONIOENCODING = "utf-8"
python -m pip install -r requirements.txt
python dry_fruits_production_analysis.py
```

By default, the local run reads `data/raw/DRY FRUIT COUNTRY WISE.csv` and writes generated outputs into `outputs/`, including plots in `outputs/figures/`. It also accepts the generated cleaned CSV. To use another raw export or choose a different input/output path, set the environment variables before running:

```powershell
$env:FAOSTAT_CSV = "C:\path\to\FAOSTAT_data.csv"
$env:DRY_FRUITS_OUTPUT_DIR = "C:\path\to\outputs"
$env:PYTHONIOENCODING = "utf-8"
python dry_fruits_production_analysis.py
```

The raw export is included so the cleaning and modeling steps can be rerun from the source data.
